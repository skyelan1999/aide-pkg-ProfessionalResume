# `.pr` · PRDB v1

`.pr` 是完整加密的单文件职业资料库，不是普通 JSON 改扩展名，也不是 SQLCipher/SQLite 数据库。解密后的 JSON 作为应用文档数据库，包含 profiles/entries、targets/research、resumes/versions、applications、tasks 等集合。没有 SQL 查询接口。

| 字节偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII `PRDB` |
| 4 | 1 | 格式版本 `1` |
| 5 | 1 | 算法套件 `1`：PBKDF2-SHA-256 + AES-256-GCM |
| 6 | 2 | 保留，必须为零 |
| 8 | 4 | PBKDF2 迭代次数，big endian uint32，固定 600000 |
| 12 | 16 | 随机盐 |
| 28 | 12 | 每次保存随机 IV |
| 40 | 可变 | 加密 JSON 字节，尾随 16 字节 GCM 标签 |

完整 40 字节头用作 GCM AAD。头中无姓名、标题、简历数量或密码校验明文。不能隐藏文件长度、格式和密码派生参数。JSON 包含 `format=professional-resume`、`schemaVersion=1`、库 ID、修订号、创建/更新时间及业务集合。最多 15 MiB 明文；拒绝未知版本、未知派生参数、格式错误、错误密码和认证失败，不尝试降级到明文。

密钥不可从 WebCrypto 导出；会话保留 CryptoKey 与随机盐，保存时生成新 IV。改密码生成新盐与新密钥。无密码重置、后门、服务端密钥托管或 SQLCipher 兼容承诺。

同一资料库可以包含多个个人、多个目标公司/岗位、多个定制简历。简历保留生成时选定资料快照及结果，目标岗位中显示最近一次导入的调查报告；旧简历保留旧报告及查询时间。简历版本是正文快照，不是完整库的时间机器。用户可以在 `custom` 记录其他字段；新增结构版本应先实现显式迁移，不静默忽略未来版本。

临时 Aide 任务使用独立文件和随机密钥，格式为 `IV(12) | ciphertext | tag(16)`，AAD 为 `PR-TASK-1`。工作区身份 SHA-256 决定存储分区；任务使用随机 192 位 ID，完整 packet 的 SHA-256 绑定回填。任务临时文件在同目录原子替换，完成/删除使用互斥目录，不能覆盖已完成任务。意外进程崩溃可能遗留 `.lock`，此时拒绝更新，管理员确认无活动调用后可清理该任务锁；不自动夺取锁。

0.1.1 的工作区/引用读取、保存与另存为保持 PRDB v1 字节格式和密钥派生不变，不采用明文 JSON、Base64 装甲或侧车数据库。所有目标只接收已加密 `.pr` 字节。
